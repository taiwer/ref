ComfyUI · MiniMax-H3 生态

一个负责怎么拍，
一个负责谁来演。

H3 Multishot 与 H3-Cast 名字相近，却处在完全不同的层面： Multishot 解决「多个短镜头如何无缝拼成一镜到底」， H3-Cast 解决「同一个角色如何跨镜头、跨生成稳定复用」。 本文拆解两者的原理、参数与协同方式。

镜头编排 参考图资产化 音画连贯 角色一致性 参数详解
01 · 定位

核心区别：时间维度 vs 内容维度

两者不是竞争关系，而是在不同维度上解决不同的问题。

H3 Multishot

镜头编排与视频拼接

把多个独立的 10–15 秒短镜头，在视觉与听觉上无缝「缝」成一段连续的长镜头。 它处理的是时间维度上的连贯性—— 上一镜的最后一帧，就是下一镜的第一帧。

一句话：它是导演，负责剪辑与串联。

H3-Cast

角色与场景资产的管理复用

让你在多次生成中稳定使用同一个角色、同一段音色、同一个场景， 不必每次手动上传参考图、重新描述外貌。 它处理的是内容维度上的一致性。

一句话：它是选角导演兼场记，负责记住每个角色。

本质 H3-Cast 其实是对 H3 原生「参考图 / 参考音频」输入方式的一次封装与持久化管理： 先存档，后调用。而 Multishot 是对多次生成结果的串联与衔接控制。
02 · 工具详解

H3 Multishot：参数与用法

核心参数几乎全部集中在 MASTER CONTROLS（节点名 H3StudioControls）中， 调好它，就能同时控制采样器与提示词生成器的节奏。

安装

# 方式一：ComfyUI Manager → Install via Git URL，填入： https://github.com/jlucasmcrell/ComfyUI-H3-Multishot # 方式二：手动克隆 cd ComfyUI/custom_nodes git clone https://github.com/jlucasmcrell/ComfyUI-H3-Multishot
注意 安装或更新后必须重启 ComfyUI，并强制刷新浏览器（Ctrl+F5 / Cmd+Shift+R）， 否则节点可能显示为红色（缺失）。

核心参数

参数说明
shot_count 镜头总数。0 = 自动模式，按脚本中 --- 分隔符的数量决定； 1–8 = 强制生成指定数量的镜头。
width / height 分辨率。默认 1280×736（横屏）或 768×1344（竖屏）。 一次生成中的所有镜头必须是同一尺寸，中途无法更改。
frames_per_shot 每镜头帧数。默认 362 帧（约 15.1 秒），是模型训练时的最大长度。 对话较短时可降到 243 帧（约 10.1 秒）。 切勿低于 124 帧，否则模型会为塞进台词而牺牲衔接「气闸」，导致声音断裂。
steps 采样步数，出厂默认 14 步。
take_seconds 时长输入。直接填你想要的秒数，节点会自动换算成帧数，比手动计算方便。

工作流操作步骤

编写剧本

每个镜头写一段提示词，镜头之间用单独一行的 --- 分隔。

设置镜头数

shot_count 设为 0 自动识别，或填 1–8 强制指定。

调整主控参数

在 MASTER CONTROLS 面板中设置分辨率、每镜头帧数与采样步数。首次使用建议保持默认值。

生成

点击 Queue。默认第一个镜头完成后会预览，确认效果后再继续后续镜头渲染。

提示词格式

# 纯文本格式（推荐） 镜头一的提示词…… --- 镜头二的提示词…… --- 镜头三的提示词…… # JSON 格式（也可用） {"prompts": ["...", "..."]}
坑 JSON 格式错误会导致直接运行失败，而不会静默回退到纯文本解析。

写作技巧：气闸与落地

开场

每个镜头（除第一个）开场时，先保持上一镜的结束姿态约 2 秒， 写呼吸、微动等安静动作，再开始对话。

收尾

每个镜头结束时，对话必须完全结束，并留出约 2 秒余量。 一句台词绝对不能跨越两个镜头，否则拼缝处声音断裂。

衔接

写当前镜头时就要想下一镜期望看到什么。 链条会把上一镜最后一帧作为下一镜起始帧，提示词首尾对齐才能让拼缝「隐形」。

补充 在单个镜头的提示词内部，你可以自由描述相机切割或切换。 H3 模型本身支持镜头内剪辑，并且会共享一条连续的音频床。
03 · 工具详解

H3-Cast：参数与用法

参数分布在三个节点中，分别负责「存」与「用」。 工作流是：先存档，后调用。

① H3 Cast Member (Save / Load) — 角色档案

用于保存单个角色。

操作说明
Create 连接 1–4 张视图图片（不同角度），可选一段 2–15 秒语音片段， 填写角色名称与描述，即可永久保存。
Load 从下拉菜单直接选择已保存角色，输出角色数据包与预览。
Update 在已有角色上追加更多视图或语音。 需先打开 confirm_update 开关，防止误操作。
存储位置 <ComfyUI用户目录>/default/minimax_h3/reference_sheets/<名称>--<ID>/
重启 ComfyUI 也不会丢失。

② H3 Scene Asset (Save / Load) — 场景档案

逻辑与角色节点一致，但用于保存地点或背景。 没有语音槽位，描述文字用于填写场景氛围与关键细节。

存储位置 <ComfyUI用户目录>/default/minimax_h3/scene_sheets/

③ MiniMax H3 Cast to Video — 合成与调用

实际生成时使用的节点，核心参数是你要「点名」的资产。

参数说明
cast_1 ~ cast_3 最多同时接入 3 个角色。 节点会自动把所有角色的视图图片填入 H3 的 9 个 ref_image 槽位， 把语音填入 3 个 ref_audio 槽位， 并自动生成带正确标签（如 <Picture 1>、<Audio 1>）的提示词。
scene_asset
scene_images		 可选接入一个已保存的场景，或直接输入一组场景图片。两者可以同时连接。
透传参数 节点将 ref_spacing、ref_strength、ref_decay 等原生参考参数原样传递给底层 H3 节点。 若你的 H3 版本不支持某个参数，它会静默跳过，不会报错。
关键用法 在 Cast to Video 中，提示词里只需要写角色的名字 （比如「Maya 走进房间」），节点会自动把名字替换成完整的 <Picture 1>: Maya — … 格式，无需手动编号。
04 · 组合

协同工作流：像拍片一样生成

把两个工具叠起来用，你就能用「脚本点名」的方式拍一部连贯的短片。

① 建档
用 H3-Cast 把主角、配角、常用场景全部保存为档案。
→
② 写本
在 Multishot 脚本里直接用名字写提示词，用 --- 分隔镜头。
→
③ 开拍
Multishot 负责把镜头串成一镜到底，H3-Cast 保证每镜都是同一个角色。
Multishot 负责

叙事流 —— 把故事拆成镜头脚本，并保证时间轴上的音画连贯。

H3-Cast 负责

角色流 —— 保证每个镜头里出现的都是同一个角色、同一个场景。

进阶 一些更高级的 Multishot 工作流（如 joeygambino 的版本）内置了名为 H3AutoRefs 的「自动选角」功能：它会扫描你的脚本， 自动从预设文件夹里匹配角色名并加载对应参考图。 这可以看作是 H3-Cast 思路的一种自动化实现。
05 · 排错

常见问题

遇到问题先看这里，能解决大部分情况。

节点显示为红色（缺失）

通常是浏览器缓存了旧的节点定义。安装或更新节点包后，务必强制刷新浏览器页面（Ctrl+F5 或 Cmd+Shift+R）。如果仍然缺失，确认已重启 ComfyUI。

运行报错 LLM API error 404

完整版工作流可能依赖本地大语言模型（如 Ollama 中的 qwen3:14b）来辅助生成提示词。

请确保已通过 ollama pull qwen3:14b 拉取了对应模型。

生成效果不连贯

依次检查三件事：

1. 提示词是否符合「气闸与落地」原则——开场留 2 秒、收尾留 2 秒。

2. 台词是否跨越了镜头（绝对不允许）。

3. 每个镜头的结尾是否为下一镜提供了合理的起始画面。

显存不够，该选哪个模型量化版本？

根据显卡显存选择 MiniMax-H3 的 GGUF 量化版本：

Q5_1 —— 适合 24–32GB 显存。
Q4_0 —— 适合 16GB 显存。

长视频生成到一半失败了怎么办

改用「可恢复的多镜头工作流」。某个镜头效果不理想时，只需重新生成该镜头，不必从头开始，能节省大量时间。

JSON 脚本格式写错了会怎样

会直接运行失败，而不会静默回退到原始文本解析。如果不熟悉 JSON，建议直接用纯文本 + --- 分隔符的写法。

Multishot 是导演，负责剪辑和串联镜头；
H3-Cast 是选角导演兼场记，
负责记住每个角色的长相和声音，
并确保他们每次都准时、正确地出现在镜头里。
